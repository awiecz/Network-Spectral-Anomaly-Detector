# Evaluation Results

Authoritative metric tables live in [`results/metrics/`](../results/metrics/). This page summarises the CICIDS2017 Friday evaluation produced by `main.py` and `tune.py`.

---

## 1. Evaluation Protocol

| Setting | Value |
|---------|-------|
| Training data | Monday benign flows only |
| Test data | Friday (DDoS, PortScan, Bot) |
| Test negatives | Held-out Monday benign windows (`benign_test_frac: 0.30`) |
| Threshold selection | Validation split (50/50 of holdout benign + attack windows) |
| Primary label rule | `majority` — window is attack when ≥ 50 % of flows are malicious |
| Secondary label rule | `any` — any single attack flow labels the window (`dual_eval: true`) |

Labels are used **only for evaluation and threshold tuning**, never for model training.

## 8. Limitations

1. **Synthetic timestamps** — CICIDS2017 CSVs contain no reliable timestamp column; capture order is used to build 1-second bins.
2. **Volumetric scope** — majority-rule evaluation focuses on DDoS and PortScan; bot detection requires different granularity (flow-level or longer horizons).
3. **Deep SVDD** — hypersphere assumption fails on spectral features (attacks are more periodic/compact than benign); excluded by validation guard.
4. **Optional outputs** — `per_attack_flow_level.csv` and `fusion_ablation.csv` are generated by `main.py` / `scripts/ablation_flow_fusion.py` when full data is available; they are not required for the headline metrics above.

```bash
# Full evaluation (requires CICIDS2017 — see data/README.md)
python tune.py --data-dir data/raw/cicids2017 --use-cache
python main.py --data-dir data/raw/cicids2017 --tuned-weights --use-cache

# Baseline ablation
python scripts/baseline_comparison.py --data-dir data/raw/cicids2017 --use-cache
```
